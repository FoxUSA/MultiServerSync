# MultiServerSync

Утилита для массовых операций на группе Linux-серверов с одинаковой структурой папок:
выполнить одну команду сразу на всех отмеченных серверах и разложить одни и те же
файлы/папки по одному и тому же пути.

Связь — SSH и SFTP (библиотека SSH.NET), интерфейс — WPF + WPF UI (Fluent).

## Раскладка на диске

```
MultiServerSync\
├─ MultiServerSync.exe     ← единственный файл в корне: лаунчер
├─ Data\                   ← ВСЁ программное
│  ├─ MultiServerSync.App.exe + библиотеки
│  ├─ manifest.json        ← версия программы, её показывает шапка окна
│  ├─ app.ico data.ico user_data.ico  ← иконки трёх папок
│  ├─ src\
│  │  ├─ App\              ← основное приложение
│  │  └─ Launcher\         ← лаунчер
│  ├─ build.ps1            ← сборка
│  └─ README.md
└─ UserData\               ← ВСЁ пользовательское
   ├─ servers.json         ← список серверов
   ├─ workspaces.json      ← вкладки: их файлы, пути, команды и отметки серверов
   ├─ settings.json        ← настройки интерфейса, история и справочник команд
   └─ logs\ГГГГ-ММ-ДД.log
```

Папку `Data` можно затирать целиком — `UserData` не затрагивается, все настройки,
вкладки и список серверов переживают обновление.

## Обновление с byfox.dev

Кнопка в «Настройках» (и, если включено, тихая проверка при запуске) читает
`https://byfox.dev/data/multiserversync/manifest.json`. Если версия там свежее
установленной, скачивается `multiserversync.zip` — полная программа, включая `UserData`.
Имя архива на сайте регистрозависимо и должно совпадать с ним буква в букву.

Порядок жёсткий: **сначала скачать, потом менять**. Каждый шаг виден полосой с процентами:
проверка → загрузка → распаковка → подготовка. Пока архив не скачан и не проверен,
в программе не меняется ничего.

Из архива берутся ровно две вещи: папка `Data` целиком и лаунчер в корне.
`UserData` из архива отбрасывается — свои серверы, вкладки и настройки остаются на месте.

Подменяет файлы не программа, а лаунчер: скачанное складывается в `Update\staged`,
программа передаёт лаунчеру свой pid и закрывается, лаунчер ждёт её выхода, заменяет
`Data` и себя (работающий exe уходит в `.old` и убирается при следующем запуске)
и запускает уже новую версию. Если что-то не удалось — откат, программа запускается
в прежней версии, а подготовленное обновление доедет при следующем запуске.

## Иконки папок

У `MultiServerSync`, `Data` и `UserData` свои иконки: `desktop.ini` с относительным путём
плюс сами `.ico` в `Data`. Архиваторы, синхронизация и переносы между компьютерами это
регулярно съедают, поэтому **при каждом запуске программа проверяет и молча восстанавливает**
и `desktop.ini`, и атрибуты, и сами файлы иконок — эталоны зашиты в сборку ресурсами.
Что было починено, видно в журнале.

## Версия

Номер лежит в `Data\manifest.json` и больше нигде не дублируется: программа читает его
оттуда и пишет в шапку окна (и на страницу «Настройки»). Обновили `Data` — обновился номер.

## Сборка

```powershell
powershell -ExecutionPolicy Bypass -File .\Data\build.ps1
powershell -ExecutionPolicy Bypass -File .\Data\build.ps1 -Version 2.0.0
powershell -ExecutionPolicy Bypass -File .\Data\build.ps1 -Package
```

Скрипт публикует программу в `Data`, лаунчер — в корень, записывает `manifest.json`
и прописывает иконки папкам. С `-Package` собирается и то, что выкладывается на сайт:
`publish\multiserversync.zip` (полная программа, `UserData` в архиве пустая — чужие пароли
выкладывать нельзя) и `publish\manifest.json`. Оба файла кладутся
в `https://byfox.dev/data/multiserversync/`.
Без параметров версия остаётся текущей, `-Bump` увеличивает последнюю цифру. Нужен .NET SDK 9 или новее.
Внешних зависимостей от папок вне проекта нет: NuGet-пакеты (WPF-UI, SSH.NET)
раскладываются в `Data` при сборке.

## Вкладки — как рабочие столы Windows

Повторный запуск программы **не открывает второе окно**: работающая копия добавляет
себе ещё одну вкладку и выходит на передний план. Вкладок можно наделать сколько угодно:
кнопка `+` слева от вкладок или Ctrl+T. На ярлыке крестик в верхнем углу закрывает вкладку
(Ctrl+W), карандаш в нижнем — переименовывает; переименовать можно и двойным щелчком.

Ярлыки перетаскиваются мышью — порядок вкладок любой и запоминается. Первая вкладка
закреплена: её нельзя ни утащить, ни обойти слева, потому что именно она «основная»
(на ней переключатель «Общая», и закрыть её нельзя).

Что у вкладок общее, а что своё:

| Общее для всех вкладок          | Своё у каждой вкладки                     |
| ------------------------------- | ----------------------------------------- |
| список серверов (добавление, правка, удаление) | какие серверы отмечены |
| справочник команд               | текст команды и режим sudo                |
| история путей на сервере        | список файлов, путь на сервере, параметры копирования |
| история команд, настройки, журнал | результаты операций                     |

Новый сервер отмечается только на той вкладке, где его завели: молча дописывать его
в цели остальных вкладок опасно. Удаление сервера убирает его отовсюду.

Вкладки и всё их содержимое переживают перезапуск программы (`UserData\workspaces.json`).

### Переключатель «Общая»

Рядом с кнопками **«Копировать на отмеченные»** и **«Выполнить на отмеченных»**
на **первой** вкладке есть переключатель **«Общая»**. Включён — кнопка запускает операцию
сразу во всех вкладках, каждая со своими файлами, путём, командой и серверами.
На остальных вкладках такого переключателя нет: там кнопки всегда только свои.

При «Общей» терминал первой вкладки показывает **сводку по всем вкладкам**: строки всех
серверов сразу, у каждой в колонке «Сервер» подписано, с какой она вкладки. «Отменить»
и «Повторить упавшие» в этом режиме действуют на все вкладки сразу.

Пока «Общая» выключена, второстепенные вкладки показываются тускло — кнопка работает
только на текущей.

Чтобы не бегать по вкладкам и не проверять, как дела, итог операции показывается прямо
на ярлыке: `✓ 5/5` зелёным, `⚠ 3/5` жёлтым, `✗ 0/5` красным, второй строкой — что это было.
Размер ярлыка фиксирован, а название на время статуса прячется, поэтому вкладки не скачут.
Метка гаснет сама через полминуты или как только вы зайдёте на эту вкладку.

## Как пользоваться

### Серверы

Таблица со всеми серверами: галочка «участвует в массовых операциях этой вкладки», имя,
IP/хост, порт, пользователь, пароль (скрыт), результат последней проверки.
В таблице кликается только галочка — данные вводятся в отдельном окне
(**Добавить** / **Изменить** или двойной клик по строке). В том же окне есть
кнопка **«Проверить подключение»** для одного сервера.

* Галочка в шапке таблицы — отметить или снять все. То же делает кнопка справа
  от надписи «СЕРВЕРЫ · ОТМЕЧЕНО N ИЗ M» в боковой панели.
* **Проверить связь** — подключается ко всем отмеченным и выполняет `uname -a; uptime`.
* Вход по паролю или по **ключу SSH** (OpenSSH, PEM, PuTTY `.ppk`, с паролем ключа или без).
  С ключом пароль сервера нужен только для `sudo`. Если не указаны ни пароль, ни ключ,
  пробуются стандартные ключи из `%USERPROFILE%\.ssh`, как у `ssh`.
* Если сервер отклонил вход, программа сама спрашивает у него список разрешённых
  способов входа и пишет, отключён ли вход по паролю или по ключу.
* Список сохраняется в `UserData\servers.json`. Пароли и пароли ключей **зашифрованы**:
  по умолчанию под учётной записью Windows (DPAPI) — ничего не спрашивается, но на другом
  компьютере их придётся ввести заново; в «Настройках» можно включить **мастер-пароль**
  (AES-256-GCM, ключ из пароля через PBKDF2) — он спрашивается при запуске, и файл
  открывается на любом компьютере.

### Умный режим

Переключатель внизу панели слева, по умолчанию выключен. Перед запуском команды или
копирования сверяется с историей запусков (`UserData\runhistory.json`): если это действие
обычно выполняется на одном сервере, а сейчас отмечен другой, на котором его давно или ни
разу не запускали, — посреди окна спросит «Выполнить» или «Отменить». Безопасные команды
(`ls`, `df`, `docker ps`, `systemctl status`…) не проверяются.

### Команда

Текст команды выполняется на всех отмеченных серверах параллельно.
Есть история команд, справочник со своими описаниями и режим `sudo -S`.

Команда уходит на сервер **через stdin** интерпретатора (`bash -s`), а не командной строкой:

* длина ничем не ограничена — можно вставлять портянки и целые многострочные скрипты,
  ничего не обрезается и не надо экранировать кавычки;
* оба потока (обычный вывод и вывод ошибок) читаются целиком, построчно и параллельно:
  вывод виден по мере поступления, ничего не теряется и ничем не помечается — в окне
  ровно то же, что было бы видно в терминале;
* `PATH` дополняется каталогами `/sbin`, `/usr/sbin` и `/usr/local/sbin` — при входе
  без терминала он часто урезан, и из-за этого «не находились» `systemctl`, `service`, `ip`;
* если сработал таймаут команды, она снимается, а всё, что успело прийти, остаётся в выводе.

Красным сервер помечается, только если команду **не удалось выполнить**: не подключились,
связь оборвалась, не дождались ответа, команду убили на сервере. Если команда отработала —
это «успешно», даже когда сама команда на что-то поругалась. Ругань видна в выводе, как и
в терминале, и решает по ней человек, а не программа: `ls` на несуществующем файле, `grep`
без совпадений и `systemctl status` остановленной службы — нормальная часть диагностики,
а не поломка сервера.

### Копирование

1. Кнопкой **«Открыть»** (или перетаскиванием в окно) собирается список локальных объектов.
   Кнопка открывает обычный проводник, в котором выбирается что угодно: файлы, папки,
   вперемешку, поодиночке или пачкой — мышью, с Ctrl, с Shift, по Ctrl+A. Добавляет всегда
   кнопка **«Добавить»**; вторая кнопка окна называется «Войти в папку» и только ходит
   по папкам — эта её роль зафиксирована Windows и не переопределяется, поэтому штатные
   диалоги и умеют либо файлы, либо папку. Разделения на «файлы» и «папки» в программе
   больше нет: на сервер и то и другое уходит одинаково.
2. Путь на сервере вводится текстом или выбирается кнопкой **«Обзор на сервере…»** —
   открывается графический обзор файловой системы одного из серверов
   (дерево слева, содержимое справа, создание папок).
3. **«Копировать на отмеченные»** — файлы уходят на все отмеченные серверы по этому пути.

Опции: перезаписывать существующие файлы; **матч по дате изменения**; сохранять дату
изменения; сверять контрольные суммы. Недостающие каталоги на сервере создаются
автоматически.

Папка всегда копируется целиком, вместе со своим именем — как в проводнике: перетащил
папку в каталог, там появилась папка. Прежняя галочка «копировать содержимое папки»
убрана: она означала обратное и путала.

Про **матч по дате изменения**: с этой галочкой отмеченный файл уходит на сервер, только
если локальный свежее серверного. Даты берутся у самого файла на сервере (одним запросом
атрибутов), запас — 2 секунды, потому что SFTP хранит время с точностью до секунды.
Пропущенные файлы видно в выводе вместе с обеими датами. В конце вывода по каждому серверу
печатается разбор: сколько файлов отправлено и на сколько байт, сколько пропущено как
«не старее», сколько пропущено потому, что файл уже есть, сколько создано папок и сколько
файлов рассмотрено всего. В таблице слева то же самое одной строкой:
«отправлено 12, 4,2 МБ · не старее 3». Полезно вместе с «сохранять дату изменения»:
тогда повторный прогон не гоняет по сети то, что уже лежит на сервере.

Про дату изменения: SFTP создаёт файл на сервере заново, поэтому его время правки
по умолчанию становится моментом загрузки. С включённой опцией после каждой передачи
выполняется SETSTAT — файлу проставляется дата изменения и доступа локального оригинала
(как `scp -p`). Папкам время выставляется последними, уже после заливки содержимого.
Если сервер или файловая система не разрешают менять атрибуты, файл всё равно
копируется, а в вывод пишется предупреждение.

Про сверку контрольных сумм (по умолчанию выключена): после копирования на сервере
запускается `sha256sum` по всем залитым файлам (пачками по 100), хеши сравниваются
с локальными. Локальный SHA-256 считается один раз и переиспользуется для всех серверов.
Расхождение или отсутствие ответа по файлу помечает сервер как неуспешный, в вывод
пишутся оба хеша. Требует `sha256sum` на сервере и заметного времени на больших объёмах.

### Нижняя панель: терминал и журнал

Весь вывод собран в одном месте — внизу окна, а не на страницах. F12 сворачивает
и разворачивает панель, граница тянется мышью.

* **Терминал** (первая вкладка) — слева на треть ширины таблица со всеми серверами
  операции (значок состояния, сервер, статус, время), справа на две трети — полный вывод
  выбранного сервера. Вывод прокручивается за новыми строками сам, пока в нём ничего
  не выделено. Сюда попадает и команда, и копирование, и проверка связи — то, что
  запускали последним. Там же прогресс «N из M», «Отменить», «Повторить упавшие»,
  кнопка «Копировать весь вывод» (текст со всех серверов сразу) и маленькая кнопка
  копирования в шапке вывода — она берёт только выбранный сервер.
* **Журнал** — живая лента всего происходящего, свежие записи сверху. Записи вкладок
  помечены её названием. Тот же текст пишется в `UserData\logs\`.

### Настройки

Версия программы, обновление с byfox.dev (кнопка «Проверить» и переключатель тихой проверки
при запуске), ссылка на сайт, тема оформления, число одновременных подключений
(по умолчанию 8), таймаут подключения и таймаут команды, быстрый переход в папки
`Data` и `UserData`.
